# 親切の点検 — `web/` を KINDNESS.md の九つの約束で見る

`KINDNESS.md` の約束を、timeline・compose・通知・設定・signup に当てた最初の表。
コードを読んだだけで、画面は動かしていない。根拠は `file:line`。
「✓」は約束に合っている、「△」は足りない、「—」は確認できなかった。

## すでに親切なところ

- **失敗の文面がやわらかい。** `うまく送れませんでした。もう一度、ためしますか?`
  (`lib/locales/ja.ts:116`)。責めず、次の一手がある。約束 1・4。
- **下書きを覚える。** ローカルに残し、ログインしていればサーバにも静かに同期する
  (`lib/compose-draft.ts:1-12`)。signup も戻せる(`routes/signup/+page.svelte:94`)。約束 5。
- **催促が静か。** メールのお願いは、画面を塞がない浮かぶカードで、「あとで」で3日黙る。
  ログイン前後と法的ページでは出ない(`lib/components/EmailNudge.svelte:1-33`)。約束 7。
- **通知を二つに分けている。** 会話(返信・DM・申請)が先、お気に入りやブーストは
  開きに来たときだけ(`routes/notifications/+page.svelte` の tier)。約束 7。
- **ミュート・ブロックがある。** プロフィールと設定から(`ja.ts:696-699`、`ja.ts:234-236`)。約束 2。

## 次の一手(小さい順)

1. **文面の一言足し**(失敗の理由・次の一手)。`ja.ts` と他言語のみ。壊すものがない。
2. **フィードバックの口。** 隅の小さなリンクから、画面名・言語・バージョンだけを添えて送る。
   送り先の受け箱(サーバ側)を、まず決める必要がある。
3. **数を隠す設定。**
4. **削除の「元に戻す」。** 連合への影響(相手のサーバへの Delete)があるので、遅らせる設計を先に決める。
