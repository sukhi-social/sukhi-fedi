# サーバーを、ゆっくり守る(はじめての管理者へ)

> 状態: **下書き。** 文中の `sukhi doctor` などは、まだ実装がない
> ([`SERVER_SHELL.md`](SERVER_SHELL.md) の設計)。文は、技術の言葉を使わずに読める形を目指して書いた。
> 技術の側の手順は [`OPERATING_OVER_SSH.md`](OPERATING_OVER_SSH.md) と [`RUNTIME.md`](RUNTIME.md)。

このサーバーには、あなたの友だちや、知らない誰かの、ことばや写真が置かれます。
ここは、それを預かる家のようなものです。家には、鍵があって、窓があって、
ときどき、古くなった蝶番(ちょうつがい)を直す日があります。
この文書は、怖がらせるためではなく、**どこが弱くなりやすいか**と、**なぜ気にかけるのか**と、
**静かにできる手当て**を、順に書いたものです。全部を一度にしなくて大丈夫です。

## はじめに: 自分で持つか、迎えてもらうか

サーバーを自分で持つことは、**学ぶ気持ちがあれば、きっとできます。**
わからないところは、一緒に確かめながら進められます。この文書も、そのために書きました。

ただ、サーバーは**預かりもの**でもあります。止めたくない日に止まったり、夜に気にかける日があったりします。
そのため、いまの暮らしの中で、手が回らなそうだと感じることもあると思います。それは、悪いことではありません。

そのときは、**自分でサーバーを持たない道**があります。

- **sukhi.social の中に、小さな独立したコミュニティを作る。** 場所と見守りは任せて、
  あなたは、そこに集まる人たちの雰囲気を育てる役になれます。
  (どんな形で実現するか ─ 管理者の権限をどこまで渡すか、データはどう分けるか ─ は、これから決めます。**現時点では未定です。** 見守りの考え方の案は [`COMMUNITY_SUPPORT.md`](COMMUNITY_SUPPORT.md)。)
- 迷ったときは、先に聞いてください。決める前の相談で構いません。
  - Matrix: `#sukhi-social:matrix.org`
  - メール: `<連絡先のアドレスを、ここに入れる>`

**向き不向きを測るためのものではありません。** 次の問いに「うん」が多いなら、自分で持つ道が楽しくなりそうです。
少なければ、迎えてもらう道が、きっと心地よいです。

| 問い | |
| --- | --- |
| 仕組みを知ることが、楽しいと感じる | |
| 月に数時間、サーバーのために使える | |
| 夜に連絡が来たとき、落ち着いて見られる | |
| わからないとき、聞くことができる | |
| 預かっている人たちの暮らしを、少し気にかけたい | |

どちらを選んでも、同じ家の仲間です。途中で道を変えてもよいです。

## 先に、安心してほしいこと

- 完璧に守る必要はありません。できる範囲で、続けることのほうが大切です。
- 何か起きても、**戻れるようにしておけば**、たいていのことはやり直せます(§3)。
- わからないときは、止まって聞いてください。聞くことは、恥ずかしいことではありません。

## 六つの、弱くなりやすいところ

### 1. 鍵(入るための合図)

**どこが弱いか。** パスワードや鍵は、人の手で使うものなので、使い回し、書き留めた紙、
チャットに貼ってしまったもの、から、静かに漏れます。
**なぜ気にするか。** 鍵を持つ人は、あなたと同じことができます。サーバーの中身を見ることも、消すことも。
持ち主が気づかないうちに入られることが、いちばん困ります。
**静かな手当て。** 鍵に**合言葉(パスフレーズ)**を付ける。パスキーやセキュリティキーを使う。
鍵を人に渡さない。使わなくなった鍵は、サーバーから外す。
**sukhi がすること。** 入れる鍵の一覧と、いつから使われていないかを見せる。古い鍵は、そっと「まだ使いますか?」と聞く。

### 2. 古くなった部品

**どこが弱いか。** サーバーは、たくさんの部品でできています。部品は、時間が経つと、
「ここに弱いところが見つかりました」と作った人たちが知らせてくれて、直された新しいものが配られます。
**なぜ気にするか。** 弱いところの知らせは、**誰にでも見える**ので、直していないサーバーは、探している人に見つかりやすくなります。
**静かな手当て。** 直された部品を、定期的に入れ替える。急ぐ必要がある日は、そう知らせてもらう。
**sukhi がすること。** 「いちばん古い部品は、何日前のものですか」を見せる。入れ替えるときは、
先にみんなに知らせて、少しだけ待ってから、静かに再起動する(`sukhi release`)。

### 3. 消えたときに、戻れるか(バックアップ)

**どこが弱いか。** 守りがどんなに堅くても、機械は壊れるし、人は操作を間違えます。
**なぜ気にするか。** 預かっているものは、取り戻せないことがあります。**戻れる**とわかっていると、
他のことを、落ち着いて試せます。
**静かな手当て。** 控えを取る。そして、**取った控えから、実際に戻せるか**を、ときどき確かめる(確かめていない控えは、控えと言えません)。
**sukhi がすること。** 直近の控えの時刻と、確かめた結果を見せる。古いときは、更新の前に「先に控えを取りましょう」と言う。

### 4. 外から届くもの

**どこが弱いか。** このサーバーは、ほかのサーバーから投稿や画像を受け取ります。
全部が善意とは限らず、まれに、機械を困らせる形のものが混じります。
**なぜ気にするか。** 受け取る口は、**開いている扉**です。扉の鍵を確かめる仕組み(署名の確認)は、
アプリがやってくれていますが、アプリも部品でできています(§2)。
**静かな手当て。** アプリを新しく保つ。玄関(nginx)の前で、おかしな量の訪問を断る。
**sukhi がすること。** 受け取りの失敗や、断った数の変化を、静かに知らせる(増えたときだけ)。

### 5. 急かされること(人の気持ち)

**どこが弱いか。** 「今すぐ」「さもないと」と急かす連絡は、**人**に向けて作られています。
正しいふりをした偽の連絡で、鍵を渡してしまう事故は、とても多いです。
**なぜ気にするか。** どんな道具も、人が自分で渡してしまったら、守れません。
**静かな手当て。** 急かされたら、**一度、閉じる**。別の道(自分で開いたページ、電話)で確かめる。
パスキーは、偽のページでは働かないので、助けになります。
**sukhi がすること。** 本物の操作でも、急かさない。更新の確認は「版の番号を打ち直す」という、**ゆっくりの確認**にする。

### 6. 見えなくなること

**どこが弱いか。** 何が起きたか見えないと、困っていることにも気づけません。
**なぜ気にするか。** 気づくのが遅れるほど、直すのが大変になります。
**静かな手当て。** 記録を残す。そして、**ときどき読む**。
**sukhi がすること。** 操作の記録を、誰でも読める日本語で見せる(`sukhi audit`)。
責める道具ではなく、「何があったか、一緒に読める」ための記録にする。

## 『自分の場合は』を考えてみる

小さな表を、自分のことばで埋めてみてください。正解はありません。

| 問い | あなたの答え |
| --- | --- |
| いちばん守りたいものは? (人の投稿、写真、連絡先、……) | |
| もし失ったら、いちばん困るのは? | |
| どのくらい手間をかけられる? (毎日 / 週に一度 / 月に一度) | |
| 困ったとき、頼れる人は? | |

(考え方は、EFF の [Surveillance Self-Defense「Your Security Plan」](https://ssd.eff.org/module/your-security-plan)
の「守りたいもの・誰から・どのくらい困るか・どのくらいありそうか・どのくらい手間をかけられるか・誰が助けてくれるか」を参考にしている。
文は、この家のために新しく書いた。)

## ツールも、やさしくあること

`sukhi` の、画面に出る文章は、この文書と同じ調子で書く。具体的には:

- **責めない。** 「失敗しました」でなく「うまくいきませんでした。理由は…です。次は…してみてください」。
- **怖がらせない。** 色や記号で脅さない。赤は、本当に急ぐときだけ。
- **急かさない。** 期限があるときは、いつまでか、あとどれくらいか、延ばせるか、を並べる。
- **ひとつずつ。** 一度に出す提案は三つまで。いちばん大事なものから。
- **やめられる。** どの操作にも「やめる」がある。予行(dry-run)が既定で、本番の前に必ず止まる。
- **覚えている。** 同じことを二度聞かない。前に「あとで」と言ったことは、静かに残す。
- **わかる言葉で。** 専門の言葉が出るときは、すぐそばに一行の説明を添える。

### `sukhi doctor` — サーバーの健康診断(案)

```
$ sukhi doctor

こんにちは。サーバーの様子を見てみました。今日は、気にかけたいところが 2 つあります。

 ✓ 鍵        使っていない鍵はありません
 ✓ 控え      きのう 03:10 の控えから、戻せることを確かめてあります
 ・ 部品      いちばん古い部品は 41 日前のものです
             直された新しい部品が出ています。
             → 計画を見る:  sukhi release
 ・ 再起動    カーネルが新しくなっています。次に再起動するとき、反映されます
             (急ぎではありません。更新の日にまとめても大丈夫です)
 ✓ 記録      先週の操作は、あなたの 3 件だけでした

急がなくて大丈夫です。気になったところだけ、見てください。
```

- 出すのは、**状態の事実と、次の一手**だけ。点数や順位は付けない。
- 何も気にかけることがなければ、「今日は、特にありません」と言って終わる。
- `--json` では、同じ内容が構造化されて出る(AI も人も、同じものを読む)。
- 出さないもの: 秘密、人の投稿の内容、責める言葉。

## 読んだあとに

もし、ここまでを読んで、少し気が重くなったなら、**今日は、控えが戻せることだけ**確かめてください。
それで、ほとんどの「もしも」から、戻る道ができます。残りは、また今度で。
