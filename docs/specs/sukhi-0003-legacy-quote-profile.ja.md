# sukhi-0003: 引用の互換の形

- 状態: 草案。`fedi/builders.ex:347-364` と `ap/instructions/extract.ex:46-80` に実装済み。
- 識別子: `https://sukhi.social/spec/sukhi-0003/1`
- 土台にする仕様: FEP-e232(オブジェクトへのリンク)、FEP-044f(同意にもとづく引用)
- 型: `#QuoteNote`(「送るとき」の三つの形。英語版に書いてあります)
- 用語と「必須・推奨・任意」の意味: [README.ja.md](README.ja.md)

## 一言で

「この投稿は、あの投稿の引用です」と伝える書き方が、サーバごとに違います。そこで、引用を送るときは**三通りの書き方をすべて付け**、受け取るときは**どの書き方でも読む**、という約束を決めています。移行が終わったら、古い書き方から順に外します。

## 何が困るのか

引用の書き方は、少なくとも次の四つがあります。

| 書き方 | 使うサーバ |
| --- | --- |
| `quoteUrl` | Misskey とその派生 |
| `_misskey_quote` | Misskey とその派生 |
| `tag` の中の `Link`(FEP-e232) | FEP-e232 を実装するサーバ |
| `quote`(FEP-044f) | 新しい形。Mastodon などが読む |

どれか一つだけで送ると、それを読まないサーバには、普通の投稿に見えます(引用だと分かりません)。Misskey は、前の二つ(`_misskey_quote` と `quoteUrl`)だけを読み、`tag` の `Link` も `quoteUri` も読みません。標準には、移行のあいだにどれを送り、どれを読むべきかが書かれていません。

## 送るとき

引用の投稿には、次のすべてを、引用先の URL にして付けるのが**推奨**。

1. `quoteUrl`
2. `_misskey_quote`
3. `tag` の要素 `{"type": "Link", "href": <URL>, "rel": "_misskey_quote"}`(FEP-e232 の形)

FEP-044f を実装したら(まだ。`FEDERATION.md` の §11)、`quote` も付けるのが**推奨**。その場合、`@context` に必要な語を、署名する**前**に入れるのが**必須**。後で足すと、署名の対象に含まれないため。

## 読むとき

引用先の URL は、次のどれかから取るのが**推奨**。

`quoteUrl`、`quoteUri`、`_misskey_quote`、`tag` の `Link` で `rel` に `_misskey_quote` か `e232` を含むもの。

読む処理は一か所にまとめてよい(**任意**。sukhi はそうしている)。FEP-044f を実装したら `quote` を加える。現在のコードは `quote` を読まない。

## 同意について

引用される側が「引用してよい」と決める仕組み(FEP-044f の `QuoteRequest` と `QuoteAuthorization`)は、まだ処理していません。その仕組みを持つ投稿を引用すると、受け取る側では「古い形の引用」として扱われます。

## いつ外すか

どの書き方も、sukhi と連合しているサーバのどこにも必要とされなくなったら、外すのが**推奨**。外すときは、この仕様の新しい主番号(`/2`)として出す。
