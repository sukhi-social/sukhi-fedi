# sukhi の仕様(日本語版・読み方)

ActivityPub や HTTP の知識がなくても読めるように書き直した版です。前提にしているのは、「もし A ならば B」「B でないなら A でない」といった基本的な論理が分かることだけです。英語版が正本で、食い違いがあれば英語版を直します。

## 先に知っておく言葉

| 言葉 | ここでの意味 |
| --- | --- |
| サーバ | ActivityPub で投稿をやりとりする、一つ一つの運営単位。sukhi もその一つ。 |
| actor(アクター) | 「だれが」にあたるもの。ユーザーの口座のようなもの。URL で名前が付く。 |
| activity(アクティビティ) | 「何をした」にあたる一通のメッセージ。投稿する、フォローする、など。 |
| inbox(受信箱) | サーバが activity を受け取る窓口の URL。 |
| 署名 | 送り主が「この鍵を持つ者が送った」と証明するための印。鍵の持ち主だけが作れる。 |
| ダイジェスト | 本文から計算した短い値。本文が一文字でも変わると別の値になる。 |

## 必須・推奨・任意

仕様の文では、守る強さを三つの語で書き分けます(RFC 2119 に従う用法です)。

| 語 | 意味 | 守らないと |
| --- | --- | --- |
| 必須(MUST) | 守らなければならない | 他のサーバと通信できない、データを失う、安全でなくなる |
| 推奨(SHOULD) | 特別な理由がなければ守る | 動くが、他のサーバに迷惑がかかる、または効率が落ちる |
| 任意(MAY) | 好きにしてよい | 何も起きない(sukhi がそうしている、というだけ) |

「必須」は、真似をした実装が通信できなくなる場合に限って使っています。
